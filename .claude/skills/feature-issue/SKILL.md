# feature-issue: 기능 요청 → 이슈·라벨·워크트리

기능 요청이 들어오면 **구현보다 먼저** 이슈를 만들어 작업 기록을 남기고, 그 이슈 번호로 워크트리를 연다.
이슈 생성은 공개 저장소에 쓰는 동작이므로, 아래 중복 검사를 반드시 거친다.

- 라벨 세트: `references/labels.md`
- 본문 템플릿: `references/issue_template.md`
- 스크립트: `scripts/create_feature_issue.py` (gh 래퍼, 중복 검사·라벨 생성·이슈 생성·워크트리 생성)

## 작업 순서

### 1. 요청 확인

요청이 새 기능 또는 새 분석 추가인지 확인한다. 요청에 목적이 빠져 있고 추측할 수 없으면 한 번만 묻는다.
추측할 수 있으면 묻지 않고 진행하며, 가정한 내용은 최종 보고에 적는다.

### 2. 제목·본문 작성

- **제목**: 한국어 명사형, 60자 안팎, 마침표 없음. 예: `혼잡도 시간대별 집계 추가`
- **본문**: `references/issue_template.md`를 따라 임시 파일에 쓴다.
  - 임시 파일은 저장소 밖(scratchpad)에 둔다. 저장소에 본문 파일을 남기지 않는다.
  - 목적과 완료 조건 위주로 쓴다. 수치는 확인된 것만 쓰고, 모르면 "미정".
  - 템플릿의 주석 블록(`<!-- -->`)은 지우고 쓴다.

### 3. 라벨 선택

`references/labels.md`에서 고른다.
- 유형 1개 (`기능` / `개선` / `버그` / `문서`) — 필수
- 주제 0~1개 (`혼잡도` / `OD` / `환승` / `운임` / `데이터`) — 파일 경로로 판단
- 세트에 없는 라벨은 만들지 않는다.

### 4. 생성

```bash
python .claude/skills/feature-issue/scripts/create_feature_issue.py \
  --title "혼잡도 시간대별 집계 추가" \
  --body-file "<scratchpad>/issue_body.md" \
  --type 기능 --topic 혼잡도 \
  --slug congestion-hourly --worktree
```

- `--slug`는 영문 소문자·숫자·하이픈만 쓴다. 브랜치 이름에 들어간다.
- 먼저 계획만 보고 싶으면 `--dry-run`을 붙인다 (중복 검색은 수행하고 생성은 하지 않는다).
- 스크립트는 gh 로그인 확인 → 중복 검색 → 없는 라벨만 생성 → 이슈 생성 → 워크트리 생성 순서로 진행한다.

종료 코드별 대응:

| 코드 | 의미 | 대응 |
|---|---|---|
| 0 | 성공 | 4단계 보고로 진행 |
| 2 | gh 미로그인 | 사용자에게 터미널에서 `gh auth login`을 직접 실행하도록 안내. 자격 증명을 내가 입력하지 않는다. 로그인 전까지 이슈 초안만 채팅에 보여준다. |
| 3 | 유사 이슈 있음 | 새로 만들지 않았다. 기존 이슈 링크를 보여주고, 그 이슈로 작업할지 새 이슈를 원하는지 묻는다. |
| 1 | 그 밖의 오류 | 스크립트 출력(stderr)을 그대로 보여준다. 원인을 고쳐 다시 실행한다. `--force` 같은 우회 옵션은 없다. |

### 5. 보고

성공하면 아래를 짧게 보고한다. 이슈 링크는 `owner/repo#N` 대신 **전체 URL**로 쓴다.

- 이슈: 전체 URL, 제목, 라벨
- 워크트리 경로와 브랜치 (`feature/<번호>-<슬러그>`, 기준 `main`)
- 가정한 내용 (있을 때만)

### 6. 워크트리에서 구현

이후 구현은 워크트리 경로에서 진행한다. 메인 저장소의 작업 트리는 건드리지 않는다.
커밋은 `data-commit` 스킬로 하며, 이 스킬은 커밋과 push를 하지 않는다.

## 범위 밖

- 이슈 수정·닫기·댓글은 하지 않는다. 사용자가 요청하면 별도로 처리한다.
- 커밋 메시지에 `Refs #N`을 넣는 연결은 아직 하지 않는다 (후속 과제).
- 라벨 세트에 없는 라벨은 생성하지 않는다.
- 이슈나 워크트리 삭제는 사용자가 명시적으로 요청할 때만 한다.
